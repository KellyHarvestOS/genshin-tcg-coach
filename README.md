Card Coach анализирует изображение экрана, восстанавливает состояние партии и просчитывает варианты на несколько ходов вперёд. Он объясняет рекомендацию, показывает альтернативы и может озвучить совет. **Все ходы в игре вы делаете сами.**

> [!IMPORTANT]
> Это советник, а не игровой бот. В проекте нет управления клавиатурой или мышью и доступа к памяти игры. `DRY_RUN` всегда включён и не может быть отключён. Это закреплено тестом `tests/test_session_and_safety.py::test_no_game_control_code`.

**Возможности:** планирование ходов с учётом правил и возможных ответов противника · распознавание состояния по экрану · проверка результата вашего хода · голосовые советы · разбор партии.

## 🚀 Запуск

Двойной клик по ярлыку **«Card Coach»** на рабочем столе или по `Card Coach.bat` в папке проекта откроет отдельное окно приложения без консоли. Кнопка **«Поверх»** держит окно поверх игры.

```powershell
.venv\Scripts\python run_coach.py            # окно приложения
.venv\Scripts\python run_coach.py --browser  # то же в браузере: http://127.0.0.1:8765
.venv\Scripts\python run_coach.py --demo lethal
.venv\Scripts\python -m pytest -q            # тесты (Genshin не нужен)
```

Первая установка: `python -m venv .venv` и `.venv\Scripts\pip install -r requirements.txt`.

## 🎮 Как пользоваться во время партии

1. Откройте партию в Genshin Impact (удобнее в оконном или безрамочном режиме).
2. В коуче нажмите **«Партия»** и укажите составы обеих команд, а по возможности и карты в руке. Персонажи и карты подставляются из базы вики.
3. Нажмите **«Захват»** (F9) или включите **«Слежение»**. В режиме слежения коуч сам анализирует экран, когда картинка изменилась и перестала меняться после анимации.
4. Выполните рекомендованный ход в игре сами. Коуч сравнит состояние до и после и покажет результат: «Ход подтверждён», «Сыграно другое действие» или «Action result uncertain». Затем он пересчитает план.
Совет звучит голосом после каждого анализа экрана (F8 — повторить, кнопка с динамиком — вкл/выкл). Женский голос Google Chirp 3 HD включается ключом Google Cloud Text-to-Speech: меню «⋯» → «Голос и озвучка» (или `GOOGLE_TTS_API_KEY` в `config.toml`). Без ключа говорит голос Windows. В Google уходит только текст совета.

5. В конце партии: меню «⋯» → «Завершить партию и разобрать». Разбор сохраняется в `data/matches/<id>/report.md`.

Если состояние распознано неуверенно (уверенность ниже `CONFIDENCE_THRESHOLD`), коуч не даёт совета и пишет: «Не удалось уверенно распознать состояние. Обновите экран или сделайте скриншот». Если «чей ход» определён неверно, нажмите на плашку хода в шапке, и он переключится.

## 📚 Откуда данные

Все персонажи, навыки, призывы, статусы и карты импортируются со страницы [«Список карт» на русской вики](https://genshin-impact.fandom.com/ru/wiki/Священный_призыв_семерых/Список_карт). Импортёр читает через MediaWiki API те же категории, из которых собраны таблицы этой страницы.

```powershell
.venv\Scripts\python -m gcoach.tools.wiki_import            # скачать заново и пересобрать базу
.venv\Scripts\python -m gcoach.tools.wiki_import --offline  # пересобрать из кэша wiki_raw.json
```

- Результат лежит в `gcoach/knowledge/data/`: `characters.json`, `cards.json`, `summons.json`, `statuses.json`, `reactions.json`, `manifest.json` (статистика и ссылка на источник).
- Текст эффектов превращается в механику регулярными выражениями: урон, стихия, стоимость, пронзающий урон, призывы, щиты, снижение урона, инфузии, бонусы урона и так далее. Всё, что разобрать не удалось, остаётся текстом с пометкой «не смоделировано». Движок такие эффекты **не выдумывает**, а советник не предлагает несмоделированные карты.
- **Таблица реакций** взята со страницы правил английской вики (`Genius Invokation TCG/Rules`). На русской вики страницы правил нет: её страницы реакций ссылаются на несуществующий раздел.
- **Пробелы русской вики.** Для части карт страниц нет (например, «Смена дежурства», «Мясные рулетики с мятой»), поэтому в базе их тоже нет.

Текущая статистика импорта: 174 персонажа, 567 навыков (436 разобраны полностью), 82 призыва (76 смоделированы), 342 карты действий (120 смоделированы), 11 реакций.

## 🧠 Архитектура

```
Экран ─► screen_capture ─► vision + ocr ─► reconstruct ─► GameState
                                                            │
      verification ◄─ (вы ходите сами) ◄─ UI ◄─ recommendation ◄─ planner ◄─ rules engine
```

| Модуль | Что делает |
|---|---|
| `gcoach/core` | Модели `GameState`, `Action`, `Observed` (значение + уверенность + KNOWN/INFERRED/UNKNOWN), оплата кубиками |
| `gcoach/knowledge` | Импорт с вики и типизированная база знаний |
| `gcoach/rules` | Детерминированный движок правил: проверка и стоимость действий, урон, реакции, щиты, статусы, призывы, энергия, кубики, конец раунда, победа |
| `gcoach/ai/generator.py` | Все легальные действия, с отсечением бессмысленных |
| `gcoach/ai/evaluation.py` | Оценка позиции по 14 признакам: HP, живые персонажи, энергия, кубики, карты, призывы, статусы, темп, подготовка реакций, возможность добить, угроза и др. → шанс победы |
| `gcoach/ai/opponent.py` | Модель противника: скрытые кубики дают вероятность, что он оплатит действие; скрытые карты не симулируются |
| `gcoach/ai/planner.py` | Expectimax с beam-поиском, итеративным углублением, таблицей транспозиций и лимитом времени; в критических позициях глубина растёт автоматически |
| `gcoach/ai/recommendation.py` | Действие, почему, стоимость, ожидаемый результат, план, риск, уверенность, до 3 альтернатив |
| `gcoach/verification` | Что изменилось между скриншотами и совпало ли это с прогнозом |
| `gcoach/memory` | Краткосрочная память, память партии, разбор после партии |
| `gcoach/providers` | `AIProvider`: `MockProvider` (по умолчанию, офлайн), `ClaudeProvider`, `LocalProvider` (Ollama) |
| `gcoach/screen_capture`, `vision`, `ocr` | Захват экрана (только чтение), распознавание по шаблонам и цвету, OCR чисел |
| `gcoach/server`, `gcoach/web` | Локальный сервер и интерфейс |

### Планирование

- **Наши узлы.** Каждое действие симулируется, потом сортируется по оценке, и глубже рассматриваются лучшие `BEAM_WIDTH` (к глубине луч сужается). Быстрые действия глубину не расходуют.
- **Узлы противника.** Значение считается как `λ·худший_ответ + (1−λ)·ожидание` (`ROBUST_LAMBDA`). Противника не считаем ни глупым, ни всезнающим.
- **Граница поиска.** Поиск останавливается в конце раунда. Кубики перебрасываются, поэтому следующий раунд оценивается эвристикой, а не угадывается.
- **Предпочтения.** Из двух выигрывающих линий выбирается более быстрая и та, где противник не успевает ходить.

## 👁️ Распознавание экрана и калибровка

Координаты интерфейса лежат в `assets/layouts/default_16x9.json` в долях ширины и высоты окна игры. **Разметка по умолчанию приблизительная и не проверялась на реальных скриншотах Genshin.** Перед реальной игрой её нужно откалибровать:

```powershell
.venv\Scripts\python -m gcoach.tools.calibrate мой_скриншот.png
```

Команда рисует все области поверх скриншота (`*_layout.jpg`) и печатает, что в них распознано. Подвиньте доли в JSON, пока рамки не лягут на значки HP, энергию и счётчики кубиков, затем поставьте `"calibrated": true`.

Шаблоны расширяются без изменения кода: положите PNG в `assets/<категория>/`, имя файла должно совпадать с id из базы.

```powershell
.venv\Scripts\python -m gcoach.tools.make_template shot.png --category characters --name "Дилюк" --rect 700,620,160,200
.venv\Scripts\python -m gcoach.tools.make_template shot.png --category ui/digits --name 7 --rect 690,610,18,26
```

Для надёжного чтения чисел нужны шаблоны цифр 0–9 в `assets/ui/digits/` или установленный Tesseract (`OCR_ENGINE = "tesseract"`). Пока ни того ни другого нет, OCR отключён, и коуч честно сообщает, что состояние не распознано.

Как распознаётся каждый элемент:

- **HP и число кубиков** — OCR;
- **энергия, аура и грани кубиков** — по цвету;
- **активный персонаж** — по сдвигу карты к центру;
- **поверженный персонаж** — по серой карте;
- **персонажи, карты и призывы** — по шаблонам.

## ⚙️ Настройки (`config.toml`)

`SCREEN_REGION`, `MONITOR`, `OCR_ENABLED`, `DEBUG_MODE`, `PLANNING_DEPTH` (3), `BEAM_WIDTH` (10), `LETHAL_DEPTH` (5), `CONFIDENCE_THRESHOLD`, `AI_PROVIDER`, `AI_MODEL`, `AI_TIMEOUT`, `SCREENSHOT_INTERVAL`, `LOG_LEVEL` (ERROR/WARN/INFO/DEBUG/TRACE) и др. Любую настройку можно переопределить переменной окружения `GCOACH_<ИМЯ>`.

### 🤖 Claude (необязательно)

`AI_PROVIDER = "claude"` и ключ в `ANTHROPIC_API_KEY`. Claude вызывается **только по кнопке**: «Объяснить» или комментарий к разбору партии. Все игровые расчёты локальные. По умолчанию модель `claude-opus-5-5`. Включён серверный fallback: если запрос отклонён, API повторяет его на другой модели.

## 🔧 Отладка

Меню «⋯» → «Отладка» или клавиша <kbd>`</kbd>. Вкладки:

- скриншот с распознанными областями;
- таблица уверенности по полям (KNOWN / INFERRED / UNKNOWN);
- кандидаты;
- дерево планов;
- журнал;
- сырой `GameState`.

Диагностические изображения сохраняются в `debug/screenshots/`.

## ⚠️ Известные ограничения

- Разметка экрана не откалибрована, и шаблонов персонажей и цифр пока нет. Без калибровки и составов команд, заданных в «Партия», распознавание реального экрана будет неуверенным.
- Смоделирована только часть эффектов карт и статусов, остальные помечены. Пассивные навыки персонажей не моделируются.
- Статусы и экипировка с экрана пока не читаются, они переносятся из предыдущего состояния (INFERRED).
- Выбор нового активного персонажа противника после поражения моделируется эвристикой.

## 🔤 Шрифт Genshin

Интерфейс использует шрифт интерфейса Genshin Impact (SDK_SC_Web, с кириллицей) из **вашей установленной игры**. Он не входит в репозиторий. Чтобы подготовить его заново, например после переустановки:

```powershell
.venv\Scripts\python -m gcoach.tools.extract_font            # найдёт папку игры сам
.venv\Scripts\python -m gcoach.tools.extract_font --src "D:\Games\Genshin Impact"
```

Если файла нет, используется похожий свободный шрифт Rubik.
